# Dose-aware polypharmacy ADR prediction

This folder contains a research prototype for exploring dose-aware adverse drug reaction (ADR) prediction. It is **not a clinically validated model** and must not be used to guide patient care or dosing.

## What is implemented

- `run_experiments.py` generates simulated drug-pair examples from hand-written pharmacology heuristics, trains NumPy EdgeConv-style and MLP models, prints benchmark metrics, and demonstrates a dose counterfactual.
- `faers_pair_signals.py` builds an exploratory FAERS preferred-term co-reporting disproportionality table from the supplied quarterly ASCII files. It does not train the synthetic model or claim causal/patient-level prediction.
- `generate_colab_notebook.py`, `generate_upgraded_colab_notebook.py`, and `generate_human_notebook.py` generate exploratory notebooks. Their current example labels and drug features are synthetic; the presence of reference datasets in this folder does not mean those notebooks consume them.
- The `test_*.py` files are experimental scripts and variants, not a production test suite.
- `Project_Report_ADR_Prediction.md` documents the proposed research design. Its existing numerical result tables are not supported by a checked-in run artifact and must not be interpreted as real-world validation.

## Run the current synthetic demonstration

The project uses NumPy and scikit-learn in the experiment script. From this folder, run:

```bash
python run_experiments.py
```

This run evaluates only the simulated data generated by that script. It does not read FAERS, SIDER, Decagon, PrimeKG, or MedDRA files. Some notebook-generation scripts seed drug features with Python's process-randomized `hash()`, so the NumPy seed alone does not make notebook features reproducible across processes.

## Data inventory

The folder includes FAERS 2026 Q1/Q2 ASCII files, Decagon pair and monotherapy tables, SIDER/MedDRA TSVs, a PrimeKG CSV, and a side-effect classification table. The first real-data pipeline uses the FAERS demographic, drug, reaction, and deletion tables. The other sources remain reference material and are not yet integrated. The FAERS pipeline reports at the preferred-term (PT) level because the supplied files do not include a verified PT-to-SOC hierarchy mapping.

## FAERS report-level signal pipeline

Run from this folder (Python 3.10+; standard library only):

```bash
python faers_pair_signals.py \
  --data-root . \
  --quarters 2026q1 2026q2 \
  --work-db work/faers_signals.sqlite \
  --output outputs/faers_pair_pt_signals.csv
```

The script selects the latest supplied case version, excludes case IDs in the selected quarters' deletion lists, uses `PROD_AI` where available (otherwise `DRUGNAME`), creates unordered within-report drug pairs, and joins them to reported reaction PTs. By default it includes all recorded drug roles; optionally use `--roles PS,C` to limit roles. `--min-pair-reports` defaults to 20, `--min-joint-reports` to 3, and reports with more than 300 distinct drug strings are stopped to prevent extreme pair expansion (raise `--max-drugs-per-report` if justified). The SQLite working database can be large; provide adequate disk space and keep it if you need an auditable intermediate, or remove it after preserving the CSV and configuration.

The CSV contains pair/report counts, PT/report counts, joint counts, and a continuity-corrected reporting odds ratio (ROR) with a Wald 95% interval. Only observed pair/PT combinations meeting the count thresholds are emitted. The denominator is the set of retained distinct case IDs; the 2x2 cells mean co-reported/not co-reported in that report. Non-reporting is **not** a confirmed negative clinical outcome. The default includes every FAERS reaction PT, including terms that may describe medication-use or administrative issues rather than a clinical ADR. To restrict an analysis, pass `--pt-allowlist path/to/terms.txt` with one exact PT per line; define and preserve that list as part of the study protocol. This exploratory ranking does not estimate incidence, causality, or an individual's risk. Results can be affected by duplicate submissions not sharing a case ID, indication/confounding, reporting intensity, drug-name quality, and report selection. FDA cautions that raw FAERS data do not by themselves establish a drug-event relationship or support drug-to-drug safety comparisons ([FDA data limitations](https://www.fda.gov/drugs/cder-conversations/understanding-cders-postmarket-safety-surveillance-programs-and-public-data)).

This first pass does not harmonize doses, map PTs to SOCs, compute adjusted or stratified signals, or use Decagon/SIDER/PrimeKG. It deliberately avoids treating unreported reactions as clinical negatives.

The checked-in run used Q1 and Q2 2026 with all drug roles, `--min-pair-reports 20`, `--min-joint-reports 3`, and `--max-drugs-per-report 300`. It retained 792,346 distinct case IDs and emitted 10,166,508 observed pair/PT rows. The generated CSV is large (about 1.1 GB); run metadata is in `outputs/faers_pair_pt_signals.csv.metadata.json`, and the SQLite staging database is in `work/faers_pair_signals_v4.sqlite`.

For a smaller candidate review file, run:

```bash
python faers_signal_review.py \
  --work-db work/faers_pair_signals_v4.sqlite \
  --output outputs/faers_pair_pt_review_top1000.csv \
  --min-pair-reports 100 \
  --min-joint-reports 10 \
  --min-pt-reports 1000 \
  --min-contrast-cell-count 20 \
  --top-n 1000 \
  --require-ci-lower-above-one
```

This emits a compact ROR-ranked review list, not “significant findings”: p-values and multiplicity correction are not computed. Review PT meaning, source reports, duplicate/reporting bias, and confounding before describing any individual row.

## Work required before claiming a complete data-driven implementation

1. Build and document a reproducible FAERS/Decagon/SIDER/PrimeKG ingestion and identifier-mapping pipeline.
2. Define an outcome and sampling strategy that handles unlabeled pairs and reporting bias without treating unreported events as negatives.
3. Train and evaluate on provenance-tracked real data with patient/report and drug-held-out splits; save run configuration, predictions, and metrics.
4. Reconcile the report's target count, feature dimensions, drug cohort, model description, and tables with the actual code and run artifacts.
5. Add unit/integration checks, a lockfile or pinned environment, and a clean command-line entry point.

Until those steps are complete, describe the model as a **synthetic research prototype** and the new FAERS pipeline as an **exploratory report-level association analysis**, not as a complete or clinically validated ADR prediction system.
